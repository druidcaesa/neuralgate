## 1. 产品概述

### 1.1 产品名称

NeuralGate — Go自研企业级AI大模型治理网关

### 1.2 产品Slogan

统一大模型入口 · 生产级流式审计 · 国产环境全兼容

### 1.3 产品定位

轻量、高性能、可商业化的私有化AI模型网关，解决国内政企、集成商私有化大模型落地的合规与兼容痛点。区别于通用开源网关，主打**国内生产级审计合规 + 信创软硬件兼容**。

### 1.4 目标用户

| 用户类型 | 典型角色 | 核心诉求 |
|----------|----------|----------|
| 中小软件集成商 | 项目经理/架构师 | 可快速集成的AI网关，支持信创环境 |
| 政企信息化项目 | 甲方IT负责人 | 合规审计、国产适配、数据不出域 |
| 企业内部AI平台 | 平台开发工程师 | 多模型统一接入、统一鉴权限流 |
| 私有化部署团队 | 运维工程师 | 单二进制部署、低运维成本 |

### 1.5 核心痛点解决

| 痛点 | 现有方案缺陷 | NeuralGate解决方案 |
|------|-------------|-------------------|
| SSE流式日志丢失 | 开源网关丢片段、断连无日志 | 环形队列异步审计 + 断连自动补全 |
| 无国产数据库适配 | 无法落地信创项目 | 达梦/人大金仓完整驱动适配 |
| 日志可篡改 | 不满足等保要求 | SHA256存证 + 审计库独立权限 |
| 无多租户隔离 | 企业级需求无法满足 | RBAC多租户 + 全量操作审计 |

## 2. 用户角色与场景

### 2.1 用户角色定义

| 角色 | 说明 | 可用版本 |
|------|------|----------|
| 超级管理员 | 系统初始化用户，拥有全部权限 | OSS/Enterprise |
| 租户管理员 | 管理本租户下的API Key、模型配置、审计查询 | Enterprise |
| 普通操作员 | 查看审计日志、导出报表，不可修改配置 | Enterprise |
| API调用方 | 通过API Key调用模型代理服务 | OSS/Enterprise |

### 2.2 核心用户场景

**场景1：政企私有化大模型项目**
- 用户：某政府单位信息化部门
- 痛点：需要可过等保2.0的全链路调用审计
- 方案：部署Enterprise版，启用SHA256日志防篡改 + SIEM外推 + RBAC权限
- 验收：审计日志不可删除不可修改，所有调用可追溯

**场景2：信创兼容项目**
- 用户：某央企国产化改造项目
- 痛点：飞腾/鲲鹏CPU + 麒麟/统信OS + 达梦/人大金仓数据库
- 方案：ARM64编译 + 达梦数据库适配 + 单二进制部署
- 验收：全套信创环境下稳定运行，性能达标

**场景3：企业多模型统一接入**
- 用户：某互联网公司AI平台团队
- 痛点：多个模型API分散管理，无法统一鉴权限流对账
- 方案：部署NeuralGate，配置多个模型适配器，统一API Key管理
- 验收：一个API Key可路由多模型，统一计量对账

**场景4：AI Agent/MCP项目**
- 用户：某企业AI Agent开发团队
- 痛点：Agent工具调用行为无法审计，存在安全风险
- 方案：Enterprise版MCP全链路审计，工具调用参数与结果全留存
- 验收：所有工具调用可追溯，异常调用可告警

| Files管理 | 支持 `/v1/files` CRUD透传 | OSS+ |

| stream_options | 支持 `stream_options.include_usage` 返回流式Token用量 | OSS+ |

#### 页面生命周期

**模型配置管理页面**：
1. 进入页面 → 加载模型配置列表
2. 点击「新增」 → 填写模型配置表单 → 提交 → 返回列表
3. 点击「编辑」 → 加载配置详情 → 修改 → 提交
4. 点击「启用/禁用」 → 切换状态 → 实时生效
5. 点击「测试连接」 → 发起测试请求 → 显示结果

#### 字段约束

**模型配置 — 创建/编辑**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| name | string | 是 | 1-64字符，全局唯一 | 对外模型名称 |
| provider | enum | 是 | openai/tongyi/zhipu/deepseek | 供应商 |
| provider_model | string | 是 | 1-128字符 | 供应商实际模型名 |
| base_url | string | 是 | 合法URL格式 | 上游API地址 |
| api_key | string | 是 | 1-256字符 | 上游API Key（加密存储） |
| timeout | int | 否 | 1-300，默认60 | 请求超时(秒) |
| max_retries | int | 否 | 0-5，默认2 | 最大重试次数 |
| retry_interval | int | 否 | 1-30，默认3 | 重试间隔(秒) |
| weight | int | 否 | 1-100，默认1 | 负载均衡权重 |
| enabled | bool | 否 | 默认true | 是否启用 |
| tags | map | 否 | key/value，最多10个 | 扩展标签 |

#### 交互全分支

**创建模型配置流程**：
1. 填写表单 → 校验字段合法性 → **校验通过** → 提交 → 成功 → 刷新列表
2. 填写表单 → 校验字段合法性 → **校验失败** → 显示错误提示，停留在表单页
3. 提交 → **name已存在** → 提示「模型名称已存在」
4. 提交 → **上游连接测试失败** → 提示「上游不可达，确认保存？」 → 用户选择保存或取消
5. 提交 → **系统异常** → 提示「系统错误，请重试」

**测试模型连接流程**：
1. 点击「测试连接」 → 发送简单测试请求到上游
2. **成功** → 显示「连接正常，响应延迟: XXms」
3. **失败** → 显示「连接失败: [错误信息]」
4. **超时** → 显示「请求超时，请检查网络或增加超时时间」

#### 异常场景

| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 上游服务不可达 | 自动重试max_retries次 | 503 服务不可用 |
| 上游服务超时 | 返回504 | 504 网关超时 |
| 上游返回错误 | 透传上游错误码和消息 | 502 上游服务错误 |
| 请求体格式错误 | 返回400 | 400 请求格式错误 |
| 未知的模型名称 | 返回404 | 404 模型未找到 |
| 上游返回非预期格式 | 记录错误日志，返回502 | 502 上游响应格式错误 |

#### 前后端交互流程

**调用模型代理**（客户端 → 代理服务 :8080）：

| 步骤 | 请求方 | 动作 | 数据 |
|------|--------|------|------|
| 1 | 客户端 | POST /v1/chat/completions | Header: Authorization: Bearer {apiKey}; Body: {model, messages, stream} |
| 2 | 代理服务 | 鉴权 → 限流 → 路由 → 转换 | 内部处理 |
| 3 | 代理服务 | 转发到上游模型API | http.Request |
| 4 | 上游模型 | 返回响应 | 非流式: JSON / 流式: SSE |
| 5 | 代理服务 | 转换为统一格式 → 写回客户端 | 非流式: JSON / 流式: SSE |
| 6 | 代理服务 | 异步审计提交 | 内部处理 |

### 3.3 限流管理

#### 功能概述

多维度限流能力，支持请求频率和Token用量双重限制。

#### 功能清单

| 子功能 | 描述 | 版本 |
|--------|------|------|
| 请求频率限流 | 每秒/每分钟请求数限制 | OSS+ |
| Token用量限流 | 每分钟Token总量限制 | OSS+ |
| 租户级限流 | 按租户维度配置限流规则 | OSS+ |
| 模型级限流 | 按模型维度配置限流规则 | OSS+ |
| 限流策略 | 令牌桶/滑动窗口 | OSS+ |
| 分布式限流 | 多实例间共享限流状态 | Enterprise |

#### 字段约束

**限流配置 — 创建/编辑**：

| 字段 | 类型 | 必填 | 校验规则 | 说明 |
|------|------|------|----------|------|
| tenant_id | string | 否 | 可为空 | 租户ID（空=全局规则） |
| model_name | string | 否 | 可为空 | 模型名称（空=全模型） |
| requests_per_sec | int | 是 | 1-100000 | 每秒请求数 |
| tokens_per_min | int64 | 是 | 1-1000000000 | 每分钟Token数 |
| strategy | enum | 否 | token_bucket/sliding_window | 限流策略 |
| enabled | bool | 否 | 默认true | 是否启用 |

#### 交互全分支

**限流触发流程**（客户端无感知）：
1. 请求进入限流中间件 → 检查 `RateLimiter.Allow(tenantID, model, tokens)`
2. **允许** → 继续后续中间件
3. **超限** → 返回429，Header: `X-RateLimit-Remaining: 0`, `X-RateLimit-Reset: {timestamp}`
4. **限流器异常** → 降级放行（保证可用性优先）+ 记录错误日志

**查看审计日志列表**：

2. 设置过滤条件（时间范围/模型/状态/关键字） → 点击「查询」 → 返回结果
3. 点击某条记录 → 展开详情 → 显示完整Prompt + Response + 分片列表
4. 点击「导出」 → 选择格式（CSV/JSON） → 下载

**SSE流式审计详情查看**：
1. 点击流式请求记录 → 展开详情
2. 显示分片时间轴：每个SSE分片的序号、时间戳、内容
3. 显示重组后的完整应答文本
4. 如果是断连记录 → 显示「断连原因: {reason}」 + 「已收到分片数: N」 + 「补全状态: 已补全」

#### 异常场景

| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 审计队列溢出 | 丢弃最旧非关键事件 | 管理后台告警显示溢出计数 |
| 数据库写入失败 | 重试3次 → 写入本地文件降级 | 管理后台显示「部分日志降级存储」 |
| 数据库不可用 | 队列缓冲等待重连 | 无客户端感知，管理后台显示DB状态 |
| 分片重组失败 | 保留原始分片，标记重组失败 | 审计详情显示「分片重组异常」 |

### 3.5 日志防篡改（Enterprise）

#### 功能概述

通过SHA256存证和审计库独立权限，确保审计日志不可篡改、不可删除。

#### 功能清单

| 子功能 | 描述 |
|--------|------|
| SHA256存证 | 每条审计日志生成全局指纹 |
| 审计库独立隔离 | 业务账号无UPDATE/DELETE权限 |
| 留存策略配置 | 可配置日志保留天数 |
| 定期校验 | 后台任务扫描比对哈希一致性 |
| 篡改告警 | 发现哈希不一致时告警 |

#### 字段约束

**SHA256存证配置**：

| 字段 | 类型 | 必填 | 默认 | 说明 |
|------|------|------|------|------|
| enable_sha256 | bool | 否 | true | 是否启用SHA256存证 |
| retention_days | int | 否 | 90 | 日志保留天数 |
| verify_interval | string | 否 | 24h | 哈希校验间隔 |
| verify_batch_size | int | 否 | 1000 | 每次校验记录数 |

#### 交互全分支

**哈希一致性校验流程**：
1. 后台定时任务触发 → 按批次读取审计日志
2. 重新计算SHA256 → 与存储的 `sha256_fingerprint` 比对
3. **一致** → 更新校验时间戳
4. **不一致** → 记录篡改告警 → 管理后台首页红色告警
5. 管理员查看告警 → 可查看被篡改的日志记录
