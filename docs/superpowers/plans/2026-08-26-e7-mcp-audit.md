ServeHTTP 行为契约(全部可测)：
1. 非 POST/DELETE → 405(GET 反向通知流 YAGNI)
2. 路径解析 serverID(`/v1/mcp/servers/{id}/mcp`)→ GetMCPServer → ErrNotFound 或 !Enabled → 404 JSON-RPC error(-32600,"unknown mcp server")
3. 读 body(≤1MB 限制,超限 -32600)→ ParseRequest → 非法 → 对应 -32700/-32600
4. method==initialize → 转发上游(POST endpoint,Content-Type application/json,合并 server.Headers)→ 成功响应后 `sessions.create(callerAgent, serverID, rc.APIKeyID)` 并回写 `Mcp-Session-Id` 响应头;callerAgent=clientInfo.Name,空则兜底 req.UserAgent()
5. 其他带 Mcp-Session-Id 的请求 → 校验 get() 失败 → HTTP 404 + -32600("session expired or unknown")
6. method==tools/call → 记 startTime(rc.StartTime 亦可)→ 转发 → 响应写完后组装 plugin.MCPAuditLog(status 按 result.isError/Error 判定)调 hook、并两段式提交常规审计(auditor!=nil 时:Submit 带 base AuditLog{RequestPath},Finalize 带 AuditMeta{ResponseStatus,Duration})
7. 其余方法(tools/list 等)纯转发
8. 上游网络错误/非 2xx 且无法读出 JSON-RPC 体 → 回 -32603("upstream unavailable"),tools/call 记 failed
9. DELETE → sessions.delete + 向上游转发 DELETE(忽略其响应体),回 204

SSE 行为契约：
1. tools/call 上游响应 Content-Type 含 text/event-stream → 网关回写同 Content-Type,循环 NextSSEMessage 读帧→WriteSSEMessage 写客户端,同时累积 payload 切片
2. 出现 `"id"` 匹配请求 ID 的 RPCResponse 帧(用 mcp.ParseRequest 逆运算:直接 json.Unmarshal 到 RPCResponse)→ 停止累积但继续透传剩余帧直至 EOF
3. 流结束后按累积的最终 response 组装 hook 调用与常规审计 Finalize(duration 到流结束)
4. 客户端中途断连(r.Context().Done())→ 停止,以已累积内容记 failed("client disconnected")? 否——记 success 与否以上游最终响应为准:未拿到最终响应即断连 → 不调 hook 不落 MCP 审计(信息不足),常规审计 MarkDisconnect 即可
